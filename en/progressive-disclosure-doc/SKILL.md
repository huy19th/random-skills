# progressive-disclosure-doc

Read sources and write knowledge notes in English into the `knowledge/` folder. Readers skim at the overview level, dig deeper only when needed, and can verify every point against the source.

## The skill's reference files

**Read these before writing.** SKILL.md only describes the *process*.

| File | Defines | Priority on conflict |
|---|---|---|
| [convention.md](convention.md) | **How to write**: information levels, style, keywords, sources and quotes, naming | 1 |
| [templates/](templates/) | **Shape** of the files the agent writes: `content.html` (topic), `glossary.html` (shared glossary) | 2 |

Files the agent does **not** edit while writing notes:
* [assets/](assets/): CSS, JS, the page shell, the source-copy shell. The build inlines them into each file.
* [scripts/](scripts/): saving sources, marking quotes, building.

## Principles

1. **The source is the truth.** Every point must point to a verbatim passage in the source. A point you derived yourself → label it Inference.
2. **Save the source first, write after.** The saved copy in `knowledge/sources/` is what gets quoted, not the online page.
3. **Never invent quotes.** Quotes are copied from the saved copy. If `mark-quotes.mjs` reports a quote not found → fix the quote, not the saved copy.
4. **The agent only writes content.** Only write `content.html`, using the tag set in the template. Do not write CSS/JS, do not edit `index.html` (it is generated by the build).
5. **The build must be clean.** Only report done when `build.mjs` exits 0.

## Inputs to determine

Ask the user (only what is unclear):
- **Sources:** URL, PDF file, video, local file. There can be several.
- **Knowledge folder:** defaults to `knowledge/` in the current directory. If a `knowledge/` folder already exists, use it.
- **Topic:** by default, if a topic with the same subject already exists, **update that topic**; otherwise create a new topic. If the user says otherwise (create a new one, or update a specific topic), do what the user says.

## Folder structure

```
knowledge/
  index.html              # generated by build: list of topics, with a search box
  glossary/
    content.html          # written by agent: shared terms
    index.html            # generated by build
  <topic>/
    content.html          # written by agent
    index.html            # generated by build: the file to read
  sources/
    <source-name>.html    # saved copy of the source, with <mark id="q-…">
```

In the commands below, `<skill>` is the folder containing this SKILL.md. Temporary files (downloaded pages, subtitles, quotes.json) go in a temp folder, not in `knowledge/`.

## Process for a new topic

### Step 1 — Save the sources

For each source, create `knowledge/sources/<source-name>.html` with `make-source.mjs`. Name the file following convention.md section 7. If the source already exists in `sources/`, reuse it; do not save it twice.

| Source type | How to get the content | Command |
|---|---|---|
| Web page | Download the raw HTML: `curl -sL <url> -o page.html`. Do not use a tool that returns a summary of the page, because the verbatim text is needed. | `--page page.html` |
| JS-rendered web page (curl returns no content) | Get the main content through a browser, write it to a clean HTML file | `--html body.html` |
| PDF | `pdftotext -layout file.pdf out.txt` (poppler). No poppler → use an available PDF library (e.g. PyMuPDF), joining pages with the `\f` character. Scanned PDF (no text) → tell the user OCR is needed. | `--text out.txt` |
| Video | Get the subtitles: `yt-dlp --skip-download --write-subs --write-auto-subs --sub-langs "en.*,vi.*" --sub-format vtt -o sub <url>`. Prefer human-written subtitles over auto-generated ones. No subtitles → transcribe the speech (e.g. Whisper, VTT output) if a tool is available; otherwise tell the user. | `--vtt sub.vtt` |
| Text file, Markdown | Use it directly | `--text file.md` |

```bash
node <skill>/scripts/make-source.mjs --out knowledge/sources/<source-name>.html \
  --title "<source title>" --url "<original URL or file path>" --lang <source language> --page page.html
```

* `--text`: each `\f` character is a page break → anchor `#page-<number>`.
* `--vtt`: each ~30-second paragraph has a timestamp linking to the original video at that moment.
* After saving, re-read the saved copy: the main content must be complete, with no menus or ads mixed in. If `--page` misses content or picks up junk → extract the main content into a file yourself and use `--html`.

### Step 2 — Read the source and outline

* Read the whole saved copy.
* Write the TL;DR (L0) first. If you cannot write it → you do not understand the source yet; read it again.
* Split into point groups (`<section>`) and L1 bullets following convention.md section 3.
* Note the terms that need definitions. Open `knowledge/glossary/content.html` (if any) to see which terms are already in the shared glossary.

### Step 3 — Choose and mark quotes

* For each L1, term, and L2 point taken from the source: choose the verbatim passage that proves it (convention.md section 5).
* Write them to a `quotes.json` file, with ids continuing from the `q-…` ids already in the source file:

  ```json
  { "q-1": "verbatim passage", "q-2": "verbatim passage" }
  ```

* Run:

  ```bash
  node <skill>/scripts/mark-quotes.mjs knowledge/sources/<source-name>.html quotes.json
  ```

* A quote not found → copy it again exactly from the saved copy and re-run. Still not in the source → the point is an Inference, or drop it.

### Step 4 — Write content.html

* Copy [templates/content.html](templates/content.html) to `knowledge/<topic>/content.html`.
* Replace every `{{...}}`, delete the HTML comments, drop the sections with no content (Open questions, Terms).
* `data-created` and `data-updated`: today's date.
* Sources section: list every source linked in the file.

### Step 5 — Terms

* Terms of the topic → the Terms section in `content.html`.
* Terms already in the shared glossary → link there, do not redefine them.
* Terms another topic is also defining → move them to the shared glossary following convention.md section 4. No `knowledge/glossary/content.html` yet → create it from [templates/glossary.html](templates/glossary.html).

### Step 6 — Build and check

```bash
node <skill>/scripts/build.mjs knowledge
```

* The build generates `index.html` for each folder that has a `content.html`, plus `knowledge/index.html`.
* The build checks and exits 1 when there is:
  * a source link pointing to a missing file, or a missing `#q-…` quote
  * a source linked but not listed in the Sources section
  * a keyword pointing to an undefined term
  * an L1 bullet or term with no source and no Inference label
  * a duplicate id
* Fix `content.html` and rebuild until it exits 0.

### Step 7 — Report

Tell the user:
* The path of the file to open: `knowledge/<topic>/index.html`.
* The number of sources used; which sources could not be saved and why.
* The points labeled Inference.
* The open questions.

## Updating an existing topic

When there is a new source on an existing topic:

1. Save the new source (Step 1), mark quotes (Step 3).
2. Edit the topic's `content.html`:
   * New point: add it to the right point group by heading, do not pile it at the end of the file. No suitable group → add a new `<section>`.
   * Point duplicating an existing one: do not rewrite it, only add the new source link to that bullet.
   * New source clarifies an existing point: add to its L2.
   * New source contradicts an existing point: keep both points with their sources, record it in Open questions.
   * New source answers an Open question: put the answer in the right point group, delete the question.
   * TL;DR: rewrite it if the new source changes the overview.
   * Add the source to the end of the Sources section (keep the `[n]` numbers of existing sources). Update `data-updated`.
3. Build (Step 6) and report (Step 7), stating clearly which points were added or changed.

## Handling feedback

When the user reviews a note and gives feedback, determine which type it is and fix it in the right place:

| Feedback type | Where to fix |
|---|---|
| How to write: style, length, keyword choice, how to quote | `convention.md`: add the rule, and add the user's wrong/right pair verbatim to the ❌ Wrong / ✅ Right table of the relevant section |
| File shape: section order, tags | `templates/` |
| Look and interaction | `assets/` |
| Mistake in one specific note | Only fix that topic's `content.html`, then rebuild |
