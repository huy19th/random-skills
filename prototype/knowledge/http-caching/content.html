HTTP cache lưu lại response để dùng lại cho các request sau, giảm độ trễ và băng thông.

Response còn fresh thì dùng ngay; đã stale thì phải validate với origin server trước khi dùng.

Server điều khiển cache chủ yếu bằng header Cache-Control.

Cache hoạt động thế nào

  • Dùng lại response đã lưu là hành vi mặc định, trừ khi có yêu cầu ngăn lại

    Vì vậy, các quy định về cache tập trung vào việc ngăn cache lưu hoặc dùng lại sai, chứ không bắt cache phải lưu response nào.

  • Có 2 loại cache: shared cache (CDN, proxy) và private cache (trình duyệt)

    Phân biệt 2 loại này quan trọng vì một số directive chỉ áp dụng cho shared cache, ví dụ s-maxage và private.

  • Cache chọn response bằng cache key, tối thiểu gồm method và URI của request

    Thực tế nhiều cache chỉ cache request GET, nên chỉ dùng URI làm cache key.

    Header Vary trong response cho phép thêm một số header của request vào cache key, ví dụ Vary: Accept-Language để lưu riêng bản tiếng Anh và tiếng Việt.

Fresh và stale

  • Response fresh khi age chưa vượt freshness lifetime; ngược lại là stale 
    response_is_fresh = (freshness_lifetime > current_age)

    Age được tính từ lúc origin server tạo response, hoặc từ lần validate thành công gần nhất.

  • Freshness lifetime được tính theo thứ tự ưu tiên, lấy quy tắc đầu tiên khớp
    1. Nếu là shared cache và có s-maxage: dùng giá trị này.
    2. Nếu có max-age: dùng giá trị này.
    3. Nếu có header Expires: lấy Expires trừ Date.
    4. Nếu không có cái nào: cache có thể tự ước lượng (heuristic), xem ý dưới.
  • Khi server không ghi thời hạn, cache có thể tự ước lượng, thường bằng 10% khoảng thời gian kể từ Last-Modified

    Ví dụ: file sửa lần cuối 10 ngày trước → cache có thể coi response là fresh trong khoảng 1 ngày.

    Hệ quả: không ghi Cache-Control không có nghĩa là không bị cache. Suy luận

Validation

  • Khi response đã stale, cache gửi conditional request đến origin server để hỏi response đã lưu còn dùng được không. Việc này gọi là validation

    Conditional request thường dùng header If-None-Match (so sánh ETag) hoặc If-Modified-Since (so sánh thời gian). Suy luận

  • Origin trả 304 Not Modified → cache cập nhật metadata và dùng lại response đã lưu, không phải tải lại nội dung

Các directive quan trọng của Cache-Control

  • max-age=N: response trở thành stale sau N giây
  • s-maxage=N: giống max-age nhưng chỉ cho shared cache, và ghi đè cả max-age lẫn Expires
  • no-cache không có nghĩa là không cache: response vẫn được lưu, nhưng phải validate trước mỗi lần dùng

    Hay bị nhầm với no-store. Muốn không lưu gì thì dùng no-store.

    Dạng có tham số, ví dụ no-cache="Set-Cookie", ít được cache hỗ trợ đúng; thường bị xử lý như no-cache không tham số.

  • no-store: cache không được lưu bất kỳ phần nào của request lẫn response

    Không dùng no-store như cơ chế bảo mật: cache độc hại hoặc bị xâm nhập có thể không tuân theo.

  • private: shared cache không được lưu; private cache vẫn được lưu
  • must-revalidate: khi đã stale thì bắt buộc validate; mất kết nối đến origin thì trả lỗi thay vì dùng response stale

    Mã lỗi nên dùng là 504 Gateway Timeout.

    Chỉ nên dùng khi dùng dữ liệu cũ gây sai nghiệp vụ, ví dụ giao dịch tài chính.

  • Khi các directive xung đột, ví dụ có cả max-age và no-cache: theo directive chặt nhất
  • File tĩnh có hash trong tên (ví dụ app.3f9a.js) nên đặt max-age dài Suy luận

    Nội dung đổi thì tên file đổi, nên URL và cache key cũng đổi. Response cũ không bao giờ bị dùng nhầm.

Thuật ngữ

fresh

Response còn hạn: được dùng ngay mà không cần hỏi lại origin server.

Response là fresh khi age của nó chưa vượt freshness lifetime.

stale

Response đã hết hạn: thường phải validate trước khi dùng lại.

Response là stale khi age đã vượt freshness lifetime.

age

Thời gian đã trôi qua kể từ khi origin tạo response, hoặc từ lần validate thành công gần nhất.

Mỗi lần validate thành công, age được tính lại từ đầu.

freshness lifetime

Khoảng thời gian một response được coi là fresh, tính từ lúc origin tạo ra nó.

Lấy từ s-maxage, max-age, Expires, hoặc do cache tự ước lượng.

cache key

Thông tin cache dùng để chọn response đã lưu, tối thiểu gồm method và URI.

Có thể gồm thêm các header được liệt kê trong Vary.

validation

Cache hỏi lại origin server xem response đã lưu còn dùng được không.

Còn gọi là revalidation. Origin trả 304 nếu response đã lưu vẫn dùng được, hoặc trả response mới.
